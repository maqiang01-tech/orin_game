# 《异变纪元：幸存者编队》UI布局与交互汇总

更新时间：2026-08-27

## 一、当前UI总方向

项目当前UI方向以最新效果图为主，不照搬其他游戏界面，但吸收“状态信息常驻、入口集中、文字内容为主、竖屏单手操作”的设计思路。

核心风格：

- 末日废土、黑金、暗色背景、磨损金属按钮。
- 竖屏手机比例优先，窗口变大或变小时保持主显示区域比例，不拉伸变形。
- 首页以背景主视觉为主，不堆叠大量功能卡片。
- 底部功能入口固定常驻，作为主要页面切换方式。
- 文本内容界面使用黑金面板承载，避免回到旧版蓝色科幻框。

当前优先级：

1. 首页必须按效果图结构呈现。
2. 底部按钮必须使用同一张按钮总表切图，普通态和选中态大小一致。
3. 探索、编队、图鉴、战斗等页面逐步套用同一套黑金按钮/面板风格。
4. 旧蓝色边框、旧UI框架素材后续逐步替换。

## 二、当前首页布局标准

首页只保留效果图里的核心结构：

- 全屏背景图：废城/建筑主视觉。
- 顶部状态栏：日期、时间、玩家名、天气、基础生存数值、图鉴/设置入口。
- 底部五个导航按钮：生存、探索、编队、基地、轮回。
- 首页中间区域不额外显示任务卡、剧情卡、按钮组或文字面板。

首页当前实现思路：

- `game_manager.gd` 中首页使用 `_build_effect_home_page()`。
- 首页逻辑需要的 Label/Container 仍隐藏保留，用于避免刷新逻辑报错。
- 可见内容以背景、顶部状态、底部入口为主。

注意：

- 不要再把首页补成旧版多卡片布局。
- 首页可以后续增加轻量氛围元素，但必须符合效果图，不应抢占主视觉。

## 三、底部导航按钮标准

底部导航是当前UI对齐的重点。

按钮来源：

- 以按钮总表 `D:\image\ChatGPT Image 2026年8月27日 00_12_31 (1).png` 为主。
- 普通态和选中态必须从同一张图裁切。
- 五个按钮普通态和选中态尺寸必须一致。

标准尺寸：

- 当前脚本已统一为 `257x159`。
- 普通态：底部普通按钮行。
- 选中态：底部橙金高亮按钮行。

当前底部导航包含：

- 生存：`nav_survival_normal.png` / `nav_survival_selected.png`
- 探索：`nav_explore_normal.png` / `nav_explore_selected.png`
- 编队：`nav_formation_normal.png` / `nav_formation_selected.png`
- 基地：`nav_base_normal.png` / `nav_base_selected.png`
- 轮回：`nav_reincarnation_normal.png` / `nav_reincarnation_selected.png`

实现原则：

- Button 只负责点击、焦点、页面切换。
- 图片作为 Button 内部 `TextureRect` 子组件显示。
- 不使用 `StyleBoxTexture` 拉伸底部导航图。
- hover、focus、pressed、selected 都只切换图片，不改变按钮尺寸。
- 底部按钮整体居中，窗口缩放时等比缩小，不裁切，不超屏。

## 四、顶部状态栏

顶部状态栏当前承担常驻信息显示。

包含内容：

- 日期：DAY、上午/下午/夜晚等。
- 玩家名。
- 天气/环境状态。
- HP百分比。
- 饥饿。
- 水分。
- 体力。
- 变异值。
- 图鉴按钮。
- 设置按钮。

后续方向：

- 顶部状态栏应参考效果图保持轻量，不使用大边框。
- 小按钮使用黑金小方按钮，不再使用底部导航图缩小显示。
- 图标后续可以替换为统一金色/灰白小图标。

## 六、探索页面方向

探索系统保留之前确定的大地图/小地图方案。

探索层级：

- 大地图：显示城市脉络、固定地点、秘境、危险区辐射、路线连接。
- 小地图：资源点、秘境、随机事件、敌人、出口、特殊点。

大地图显示要求：

- 地图要足够宽，保留城市脉络。
- 秘境/危险区不能太密集。
- 危险区从秘境向外辐射。
- 地图右侧不能被裁切。
- 支持滚动/缩放/沉浸查看。

当前视觉要求：

- 地点按钮使用黑金/橙金风格。
- 连线从旧蓝色改为低透明金棕色。
- 地图外框后续继续替换为效果图黑金面板。

小地图符号约定：

- 玩家：`◎`
- 资源：`资`
- 敌人：`敌`
- 特殊点：`?`
- 出口：`出`
- 墙体：`■`

后续需要补充：

- 小地图格子UI图片。
- 资源点图标。
- 敌人点图标。
- 特殊事件图标。
- 出口图标。
- 危险等级视觉。
- 探索结果弹窗。

## 七、编队页面方向

当前编队交互逻辑目标：

- 所有伙伴方框显示所有伙伴。
- 伙伴卡显示基础状态和是否上阵。
- 上阵操作：先点击伙伴，再点击阵容九宫格。
- 如果目标格为空，直接上阵。
- 如果目标格已有伙伴，执行替换。
- 直接点击阵容方格：
  - 有人则下阵。
  - 无人则不响应。

后续UI需求：

- 伙伴列表卡片：头像、名字、职业、等级、状态、上阵标记。
- 九宫格阵位：前排、中排、后排标识。
- 选中伙伴高亮。
- 已上阵伙伴边框高亮。
- 下阵/替换反馈。
- 阵容属性加成显示。
- 阵型切换按钮。

视觉方向：

- 方框使用黑金面板，不要蓝色边框。
- 伙伴头像后续使用统一头像框。
- 状态图标需要小型化，不能挤压卡片。

## 十、按钮与交互控件标准

按钮类型：

- 底部导航按钮：图片按钮，普通/选中两态。
- 大功能按钮：继续探索、前往、主动轮回。
- 中型操作按钮：搜索、休息、撤离、调整编队、装备、技能。
- 小型顶部按钮：图鉴、设置。
- 文本列表按钮：图鉴条目、任务条目、物品条目。

交互状态：

- normal：黑色/磨损金属。
- hover：橙金高亮。
- focus：橙金高亮，不能改变尺寸。
- pressed：橙金或红色，根据操作性质决定。
- disabled：降低亮度和透明度。
- selected：底部导航使用选中态图片。

实现原则：

- 固定图片按钮使用 Button + TextureRect 子节点。
- 不用 StyleBoxTexture 拉伸固定完整按钮图。
- 需要自适应文本的按钮才使用 StyleBox/黑金面板。
- 所有按钮大小必须由组件控制，不由图片焦点态改变。
