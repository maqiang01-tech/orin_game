## 定位

V6.2 是当前完整项目的产品与系统设计基线，覆盖竖屏单机回合制 RPG、五人职业编队、大地图探索、伙伴收集、轮回推进、营地、经济、UI、技术方案和验收门。

它不是一次性执行任务，也不是直接替代当前工程状态的代码指令。S 必须把它拆成可验收的 feature/spec 子票据后再分派给 P、A、B、C、D。

## 核心锁定方向

- 竖屏单机回合制 RPG。
- 五人职业编队，默认双前排、三后排。
- 3x3 作为阵型数据容器，不做自由移动战棋。
- 战斗主轴为职业编队、前后排保护关系、战前技能与自动策略、铺垫-增幅-终结连携、职业机制反制、属性弱点、异能构式。
- 普通战斗以自动为主，高难和 Boss 支持半自动与关键技能手动释放。
- 角色构筑拆为普通攻击、职业被动、核心技能、战术技能、觉醒技、战术模块、异能构式。
- MVP 改为 Gate 0 到 Gate 5 的验收门推进，不按固定周数强推。

## 后续窗口使用规则

- S：把 V6.2 作为产品基线和需求来源，拆分成带 `ticket/revision/dispatch_id/input_hash` 的任务，不直接唤醒执行窗口泛读整本文档。
- P | 美术和策划：从 V6.2 抽取当前功能所需的玩法、技术、UI、美术、动效和验收内容，产出 `feature_design_pack.v1`。
- A | 资源生成：只使用经用户批准的 P 设计包和明确资源票据，不直接依据 V6.2 自行扩展功能范围。
- D | 功能实现：按经审批的功能规格和当前 Godot 工程实现，不把 V6.2 中的远期系统一次性塞进当前版本。
- C：检查当前票据是否符合 V6.2 相关章节、P 设计包和验收门，不对未纳入票据的远期内容做失败判定。
- B/B0：只处理当前 release unit 的资源归档、Manifest、保护和原子发布。

## 优先拆分建议

1. Gate 0：战斗沙盒，验证五人编队、3x3 阵位、保护关系、速度回合、技能资源和基础 AI。
2. Gate 1：完整首发队，验证陈末、林美、陈锋、苏晓、老周、小七、沈琳、江离的首版定位与技能数据。
3. Gate 2：探索-战斗闭环，验证主线地图、资源地图、搜索点、撤离、噪音、负重、伤势和污染。
4. Gate 3：Boss 与伤痕，验证第一篇 Boss“缝合感染体”、情报解锁、职业反制和失败原因分析。
5. Gate 4：轮回闭环，验证保留/失去规则、记忆、遗产、世界锚点、敌方轻度适应和伙伴关系。
6. Gate 5：第一篇垂直切片，整合首篇章节、UI、资源、数值和验收指标。

## 注意

文档中的倍率、概率、冷却、伤害和阈值是首轮测试参数，不作为最终平衡值。全角色内容库、所有敌人、48 章逐章脚本、完整装备词条和每张地图配置需要继续拆为独立子文档。
